## What changed and why

KeyCap displayed shortcuts and documented recording, but there was no reusable
recording field. `ShortcutField` now provides one session using TextField sm.
`onRecord(binding)` receives a shared `KeyBinding`, `onRecord(null)` removes the
binding, and `onCancel()` leaves it unchanged. The caller replaces the field
with KeyCombo or KeyList after either callback.

The field records physical `code` and canonical Ctrl, Alt, Shift flags. A fixed
name table, `shortcutNames`, supplies Windows key names without reading the
layout-dependent `key`. Num Lock digit presses normalize to top-row digits;
other numpad bindings retain their physical code and a `Num` name prefix.

The recording marker is present from mount, before the first focus notification.
The existing clear and zoom capture handlers skip it. F1 to F7 and zoom chords
therefore become bindings rather than commands. Finishing removes the marker,
blurs the input, and calls exactly one callback. Refocusing can start another
session if a caller keeps the field mounted.

Esc cancels, bare Backspace removes, and Tab or Shift Tab retains native focus
traversal. Tab cancellation runs at blur, after focus movement begins, so a
caller can replace the input without losing the traversal origin. Tab also
passes to the existing modal focus cycle. Other handled keys stop before parent
shortcuts and dialog actions.

Reserved keys keep the field recording with an error ring, an accessible
description, and the specified reason tooltip. Empty codes, input-method keys,
and composition presses are rejected; F1 to F7 retain recording priority.
Modifier presses wait for a main key. Alt alone is rejected at release, so a
valid Alt chord does not flash an error first. Repeats do not record.
Unsupported physical codes use `지원하지 않는 키`.

There are no new dependencies, IPC changes, global listeners, timers, caches,
settings persistence, or conflict registry. Caller-owned table selection,
conflicts, and persistence stay outside this component.

## Decisions I made

- Use a session callback API instead of implementing a shortcut settings store.
- Reject unsupported codes while recording, rather than emitting an invalid
  binding. The UI classifier needs tooltip reasons; the shared reserved-key
  helper is private. Contract tests guard accepted bindings against that schema.
- Keep Tab native and finish on blur. Initialize the marker at mount so initial
  focus notification timing cannot leak the first key to a capture handler.
- Add the missing width token to both design and renderer token sets, preserving
  the specified 160px value.
