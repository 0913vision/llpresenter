## What changed and why

NumberField already removed ordinary float drift from decimal arrow additions,
including 0.2 to 0.3. It still displayed 1.4 instead of 1.40 for step 0.05,
could not take a caller's large step, and committed an off-step typed value
without rounding. This request completes those missing parts of spec 10.

`largeStep` defaults to ten times `step`. Arrow movement starts at the nearest
whole step; Enter and blur round to the nearest zero-based step and then clamp
to the supplied range. The default step of 1 therefore commits 25.6 as 26.
Immediate mode still reports valid in-range typing before commit; commit mode
buffers it, and Escape cancels its draft. IME handling is preserved.

The resting value and accessible value text use the step's decimal precision,
including trailing zeroes and an attached suffix: 0.2, 1.40, and 1.00×. Parsing
accepts decimal syntax rather than JavaScript's exponent or hexadecimal
notation. The math recognizes scientific notation in the numeric step itself.
Half-step rounding accounts for binary representation error.

Generic Slider stepping remains additive, preserving continuous offsets. Only
NumberField rounds its starting value to the step grid. The existing thumbnail
percentage field retains its deferred edits and whole-percent commits.

gallery's line-spacing and speed ranges illustrate spec 10's proposals; they do
not set product defaults. Callers own valid positive step sizes and the range.
Generic sliders retain their continuous-offset behavior.
