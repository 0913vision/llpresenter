## What changed and why

The center panel of 준비 showed an empty panel for every item that is not a
song. It now follows the proposal in spec 05:

- **공지:** the header shows the set name and `슬라이드 N개`; the body shows the
  images of the set as read-only tiles (the media grid with the size class's
  column count). The tiles don't select, activate, or output anything.
- **Bible passage:** the header shows the passage. The Bible panel of 진행 is a
  `TODO(0913vision)`.
- **Media:** the header shows the media name. The media properties are a
  `TODO(0913vision)`.
- **Header, slot, and no selection:** an empty panel, as before.

The media list and the 공지 sets come from `useOtherSources`, moved out of
`QuickAdd.tsx` so both use one reader. The reader follows both document feeds
while open, keeps each document's newest revision, and releases both feeds on
close or unmount. Notice tiles use cached thumbnails and the existing
`VirtualMediaGrid`, mounting only the viewport rows and overscan.

The failed first CI run exposed a race in the existing quick-launch editing
tests. The add button exists while its settings are still loading and ignores
clicks until it is enabled. Those tests now wait for the button to be enabled
before opening its menu, for service items, Bible previews, and library songs.
The next CI run passed those tests and exposed another existing timing race: the
screen-list test read selection as soon as a row mounted, before the shared
list's selection update reached it. It now waits for the first row to be
selected before checking the operator's next choice.

## Team member's reply

### Round 1

1. **Bound notice rendering and media resources.** Replaced per-entry
   `MediaPreview` instances with cached `thumbnailUrl` images and reused
   `VirtualMediaGrid`. Media lookup uses a memoized id map. A 1,000-entry
   regression mounts only 20 tiles and thumbnail images at normal size, creates
   no video elements, scrolls to later entries, and keeps the mounted count
   bounded. The original implementation mounts all 1,000 tiles and fails the
   test.
2. **Follow long-lived panel sources.** `useOtherSources` subscribes before
   reading media and notices, compares independent revisions, rejects stale
   pushes and late initial reads, and releases both subscriptions on close or
   unmount. Tests update notice names and membership, rename and remove media,
   delete a notice set, and verify deferred-read ordering and cleanup while
   panels stay mounted. Five regression checks fail against the original
   implementation; the updated focused panel suite passes.

Rebased onto local main before the round 2 push. Exact range, final check
results, and GitHub CI URL are in the request message.

### Round 2

1. **Navigate read-only notice tiles independently of selection.** Added a
   focus-only arrow mode to `MediaGrid` and `VirtualMediaGrid`, and enabled it
   for notices. A mounted destination receives focus immediately; an offscreen
   destination receives focus after its window mounts. The underlying tile list
   records its focus stop in full-list coordinates, retaining the correct Tab
   stop when the virtual window shifts without selecting a tile. Existing
   media-view grids keep selection navigation by default.
2. Two regressions fail against the round 2 implementation and pass after the
   fix. They cover Tab entry and exit, Shift Tab returning to the last focused
   tile, Left and Right within two visible tiles, repeated row movement, Home
   and End across a 1,000-entry set, full-list ARIA positions, bounded mounted
   tiles, one Tab stop on the focused tile after each window shift, and the
   absence of selection changes or output commands. The Tab-stop assertion
   separately reproduced a wrong local index after a window shift before the
   full-list coordinate fix.

Rebased onto local main before the round 3 push. Exact range, final check
results, and GitHub CI URL are in the request message.
