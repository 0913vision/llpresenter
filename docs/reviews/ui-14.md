## What changed and why

The clear undo UI part still advertised Ctrl Z after shell-21 removed that
binding. `ClearUndo` now has no default shortcut. Its tooltip says only
"되돌리기" and omits `aria-keyshortcuts` unless its caller supplies an explicit
shortcut. F1 to F7 clear hints, click/Enter activation, and the unavailable
state retain their behavior. These UI parts display shortcut hints; they do not
register key bindings.

The design-system principle, ClearButton README, and reference card remove the
Ctrl Z clear-undo hint. The README specifies the confirmed visibility preference
as off by default and shows conditional rendering of the undo part, including
its divider. The caller owns the preference and its persistence; this request
adds no settings schema or shell wiring. Gallery/reference specimens show the
enabled preference so the component states remain inspectable.

This branch also addresses ui-13's documentation nit: Slider uses the continuous
50% to 200% control and % field, default 100%, and SlideThumbnail describes
fixed tile widths and wrapping. Integer column tracks are explicitly
compatibility behavior rather than a 2 to 8 column slider mapping.

## Decisions I made (for the lead to confirm)

Keep the existing optional `shortcut` prop for explicit assignments. Removing an
assignment removes its hint instead of reverting to Ctrl Z. The part itself does
not bind any shortcut. Preference storage and visibility integration remain with
shell/data, matching file ownership.
