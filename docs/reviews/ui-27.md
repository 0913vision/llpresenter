## What changed and why

Catalog pushes keep the background search. `SongBackground` owns the controlled
raw query across picker revision changes; a rebuilt virtual window filters the
new catalog and points at its first match for Enter. A fresh opening clears the
query. Failed media reads log the cause before updating the retry state. The
trigger and picker share the exported `NONE_LABEL` constant.

The arrangement model now provides per-song view selection and order, plus
creation by copying the current order. Default order is implicit; named orders
retain repeats and empty sequences. Creation selects the first unused numbered
name and saves in the existing one-write queue, including pending lyric input.
It is one undo step. A selected name removed by undo or a document update falls
back to 기본 without moving the lyric cursor. Read-only viewing remains allowed.

Undoing creation back to a song that had no arrangements now deletes the
optional field from the update payload. The prior canonical metadata overlay
would have retained the newly saved field. Root metadata stays preserved.

This is the model slice for the next small 구성-row request. The row, global
rename/delete service propagation, preview, and slide list remain later P2b
work. The existing main rename/delete contracts are available; this request does
not replace them with a local-only rename.
