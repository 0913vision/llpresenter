## What changed and why

### Label clicks preserve Show focus

Clicking a CheckRow or SwitchRow button preserved keyboard focus in Show, but
clicking its name focused the toggle. A following Space could toggle it again.
The Show handler looked only for a button above the mouse target. A label's
associated button is a different target, and its native focus occurs during the
label click's default action, after mouseup.

Show now resolves a label press through `HTMLLabelElement.control` to a plain
button or tab. It retains that pending focus through mouseup within the label
and through the label's own click, until the forwarded control focus or click.
Pressing the name and releasing over the wrapped button works too. Each gesture
still toggles once. Existing text field, marked list, menu, and dialog focus
exceptions remain in effect, and Prep keeps native label behavior.

Outside release, a cancelled label click, keyboard input, drag end, window blur,
and unmount clear the pending state. There is still only one pending
interaction. One window click listener was added with matching cleanup; no timer
or cache was introduced.

The lead explicitly authorized the two shell-owned files below for ui-19 only,
limited to associated label controls and the pending focus lifecycle. No other
shell-owned path changed.

### Audit finding: slider modifier commands

The audit also found that Slider consumed Ctrl Up and Ctrl Down as value
changes, preventing Show's previous/next service-item commands. Slider now
leaves Ctrl, Alt, and Windows key combinations for the window. Its ordinary
arrow keys and configured Shift increment remain covered by the existing tests.

### ui-18 nits

1. Recording keeps the physical numpad code regardless of Num Lock. Ctrl Numpad1
   stores `Numpad1`, and its display is `Ctrl Num 1`. No new runtime
   normalization rule or shared binding contract was introduced. The existing
   label-jump digit matching rule remains separate.
2. Bare `NumpadEnter` is rejected with `확인과 실행에 쓰는 키`, like bare Enter.
   The field keeps recording with its error ring and accessible reason.

## Decisions I made

- Preserve native label activation and the existing Show focus restoration path,
  rather than adding workspace props to both row components.
- Retain a label press until its default activation can focus the associated
  control. A release over a wrapped button also needs this retention.
- Fix the two extra Slider integration regressions with a modifier guard.
- Preserve physical numpad codes, as the ui-18 reviewer requested, without
  defining a new normalization rule in another owner's contract.
