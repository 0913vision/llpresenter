## What changed and why

The ui-28 round 1 review left two nits for the next ui branch.

1.  `SongPreview.tsx` now carries a `TODO(0913vision)` where it creates the
    preview `OutputRenderer`: the 무대 화면 needs a stage layout engine, and
    until the renderer has one, the preview shows the lyric layer. This matches
    the existing note in the editor README and the TODO in `ScreenPreview`.
2.  The 구성 rename reasons now use one copy style: a polite sentence that names
    the problem, like the editor's title reasons (`songTitle.ts`). The reasons
    are named constants beside `arrangementNameReason`, as the title reasons
    are.

| Case                 | Before                                  | After                                   |
| -------------------- | --------------------------------------- | --------------------------------------- |
| Empty name           | `이름을 입력하세요`                     | `구성 이름을 적어야 저장할 수 있습니다` |
| The default name     | `기본 구성의 이름은 사용할 수 없습니다` | `기본 구성의 이름은 쓸 수 없습니다`     |
| Renamed 구성 is gone | `구성을 찾을 수 없습니다`               | unchanged                               |
| Name already in song | `이미 있는 구성`                        | `이 곡에 같은 이름의 구성이 있습니다`   |

The 이름표 rename reasons in `LabelDialog.tsx` had the same two styles mixed
(`이름을 입력하세요`, `이미 있는 이름표`), so they follow the same rule:
`이름표 이름을 적어야 저장할 수 있습니다` and `같은 이름의 이름표가 있습니다`.
The new-이름표 field in the menu shows no reason while it is empty, so it is
unaffected by the empty-name wording.
