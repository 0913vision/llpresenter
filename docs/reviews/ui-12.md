## What changed and why

Moving through the 진행 slide grid could draw a blue keyboard focus outline
outside the red LIVE ring. The user chose to hide the keyboard focus border in
진행 while retaining it in 준비.

`ListBox` now exposes its existing `workspace` on the root. `ThumbnailGrid`
passes its existing workspace through `TileList`, whose optional `workspace`
defaults to 준비. Two scoped CSS rules hide the focus outline only on 진행 rows
and slide thumbnails. No event handler, Tab stop, selection ring, live ring, or
end control is removed or disabled. Existing 진행 callers already pass
`workspace="show"`, so no shell wiring change is needed for these parts.

This is the first small part B request. The continuous size control, clear undo
shortcut removal, type tokens, preview/header specs, and terminology follow
separately. No Bible chapter string changes in this request.

## Decisions I made (for the lead to confirm)

Use the existing `workspace` contract rather than adding a second focus toggle
to `ListBox` or `ThumbnailGrid`. `TileList` forwards workspace context for its
caller's styles and defaults to 준비. Scope the CSS to the row/thumbnail so
controls at row ends remain identifiable during Tab navigation.
