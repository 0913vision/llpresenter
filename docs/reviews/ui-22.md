## What changed and why

This completes the remaining P2a editor feature after the approved ui-21 model
split: the view, save connection, keyboard dispatch, and label menu. The model
and arrangement remapping already merged in ui-21 are reused. The lead's
feature-only `prep/editor/` grant is used; shell mounting remains with shell.

The editor renders numbered slide blocks with 22px label pickers and lyrics
without field chrome. The active block has a lighter surface and accent bar. It
handles newline/blank-line Enter, Ctrl Enter, Ctrl Shift N, Backspace merge,
paragraph paste, logical-line arrow navigation, and both redo bindings. It
restores the model's caret after edits, leaves IME and modified native selection
alone, and prevents late selection events from reversing a requested move. No-op
undo/redo/Backspace also release pending focus. Untouched blocks are memoized.
Main's own pushes do not steal menu or dialog focus.

One window-owned store retains each opened song's 100-step history across
selection changes and panel unmounts. Autosaves use checked base revisions,
serialize one write per song, and coalesce pending text. An early own push does
not replace newer input/history. Refusals or a newer concurrent revision retain
the draft and block edits with an explicit reload action. An applied disk-write
failure retains the edit/revision and warns. Undo saves current canonical root
metadata with restored slides/arrangements. Deletion purges cached sessions;
dispose removes subscriptions and finishes accepted writes. The host checks
`flush()` before unmounting for shutdown; a false result keeps the window and
refused draft alive, with the explicit reload action available.

The label popup supports assignment/none, a persistent app-wide color row,
inline creation, and right-click/ContextMenu/Shift F10 management. Rename uses
data-32's active `labels.rename` operation after flushing pending song saves.
Main updates unopened library songs too. The editor maps cached current, undo,
and redo label names so undo cannot reintroduce the pre-rename name. Deletion
confirms with `AlertDialog` and removes only the definition. Songs retain its
name with no color. Read-only global settings still allow choosing existing
labels. Blocked writes have tooltip reasons.

Jump keys record bare physical letters/digits, normalize numpad digits only with
Num Lock under spec 10, reject modifiers, and clear with Backspace/Delete. The
recording marker protects the field from host shortcuts. Duplicate keys remain
allowed, with warnings on both rows; menu shortcuts are plain text.

## Decisions I made

- The host creates one `SongEditorStore(api, onProblem)`, opens checked library
  documents, renders `SongEditor`, checks `flush` before unmounting, and awaits
  `dispose` before IPC shutdown.
- A rejected save preserves its local draft and offers explicit reload rather
  than silently replacing input. Global rename waits for all cached saves.
- Logical lyric lines do not soft-wrap; long lines scroll horizontally.
- Deletion confirms once, following Menu's irreversible-delete rule.
