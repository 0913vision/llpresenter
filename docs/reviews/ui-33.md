## What changed and why

- **Dragging a chip** (spec 05, LabelChip README): pressing a chip and moving
  the pointer more than 4 px starts a drag (the same threshold as dragging a
  라이브러리 row). The dragged chip gets the dragging state and the drop bar
  shows where it would land; a drop right before or after the chip shows no bar,
  because it changes nothing. Releasing moves the chip through the song's
  session (one undo step, as Alt arrows do) and selects it. Esc cancels. The
  click that ends a drag doesn't select a chip. The 기본 or read-only strip
  doesn't drag. `useChipDrag` follows the pointer on `window` only while a press
  is held and removes its listeners when it ends. `dropIndexAt` finds the drop
  position in a strip that wraps onto several rows: the row nearest the pointer,
  then the first chip whose middle is right of it.
- **새 구성** (spec 05): a command below the 구성 choices adds a 구성 to the
  song that copies the order the item plays (기본 copies file order), saves the
  song, and picks the new 구성 for this item. `SongSession.copyArrangement` is
  the editor's `createArrangement` without changing the editor's view; the
  editor's method now uses it.
- **SelectMenu commands:** `actions` draws commands after a separator, with an
  icon and no check mark; running one closes the menu without choosing. The
  Select README describes it.
- **Structure:** the 구성 row, strip, drag, and insert menu moved from
  `SongItemPanel.tsx` into `ItemArrangement.tsx`, so each component stays small.

## Decisions I made (for the lead to confirm)

- Pointer events instead of HTML drag and drop: the strip draws its own dragging
  state and drop bar, and a native drag image would duplicate them.
- 새 구성 saves the song before the item points at the new 구성, so a 예배 순서
  never names a 구성 the song file doesn't have yet.
