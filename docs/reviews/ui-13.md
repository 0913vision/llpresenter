## What changed and why

The old slide-size control changed an integer column count, so dragging caused
large size jumps. `ThumbnailSizeControl` now reports continuous percentages
while dragging and provides a synchronized % field. The field buffers typing
until Enter or blur; Escape cancels its draft. Completed interactions round and
clamp to a whole percentage.

The spec-13 values are named exports: 50% to 200%, default 100%, one percentage
point per arrow/field step, ten with Shift. No new range was assumed. The caller
owns the current value and persistence.

`thumbnailWidth` derives a fixed tile width from the available width, default
column count, token gap, and percentage. `ThumbnailGrid.tileWidth` uses fixed
tracks that wrap without stretching, and arrow navigation reads the actual
wrapped rows. An absent, non-finite, or non-positive tile width retains the
existing column layout for callers awaiting integration.

The generic `Slider` adds continuous `step="any"`, optional Shift step, and
commit events. Existing numeric-step callers retain their behavior.
`NumberField updateOn="commit"` provides deferred edits and Escape cancellation;
its default still reports valid typing immediately. These parts are reused
rather than duplicating a field or slider appearance.

## Decisions I made (for the lead to confirm)

Pointer cancellation finishes the last visible preview at its nearest whole
percentage, just as pointer release does, so a fractional transient value does
not remain. The generic slider captures the pointer only for callers using
commit events. The % field delegates text handling to NumberField's opt-in
commit mode. The range/default/steps and width mapping come directly from
spec-13; callers supply geometry and persistence.

## Shared contract change requests

None. Shell/data adopt the already-specified percentage persistence separately.
