## What changed and why

The 예배 순서 header in 진행 and 준비 now has 항목 추가 (`IconButton` sm,
`plus`, at the right end). It opens a 420 px popover (`Menu` with its search
field, placeholder `곡, 가사, 초성`) that lists the matching 라이브러리 songs
under the 라이브러리 group, with the song icon, the matched part of the title
drawn strong, and the 슬라이드 count. Choosing a song inserts it at the end of
the group that holds the selected item, or at the end of the list without a
selection (spec 05), through the same `ServiceOrderEdits` as dragging, so Ctrl Z
in the list undoes it. The popover closes after the choice. A read-only service
or no open service disables the button with the reason.

- The search is the main index (`library.search`, 20 results); an empty query
  lists the library in title order. A late answer for an older query is dropped;
  a failed search shows a notice.
- To draw the matched part, the renderer needs the index's own rules (NFC, lower
  case, no whitespace, 초성 for a query of initials only). They moved from
  `src/main/search/songIndex.ts` into `src/shared/searchText.ts`, which the
  index now imports unchanged, plus `searchRange()` that maps a match back to
  the original title.
- `Menu` items take `match` and draw that range in `body-strong` `text` (Menu
  README).

Dropping 라이브러리 songs on the 예배 순서 already works (shell's
`useServiceOrderDrag`). Filling a slot and the 다른 항목 group (머리글, 빈 자리,
성경 구절, 미디어, 공지) are the next request.

Round 1 (codex2, Request changes), answered in one new commit:

    clusters (`Intl.Segmenter`), normalizes each alone, and maps every search
    unit (not code point) back to its cluster's span. Tests: decomposed Hangul
    (NFD title, name and initials match) and a title with an emoji before the
    match.
