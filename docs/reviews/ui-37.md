Round 1 (codex2, Request changes), answered in one new commit:

1.  A memo that isn't saved stays. `setMemo` keeps the text as the item's draft
    (`memoDraft()`, at most 50 drafts) until a save succeeds; a refusal shows
    `메모 저장 실패` with `다시 저장`, which saves the draft again. The field
    shows the typed text, then the store's draft, then the saved memo, so the
    draft is back when the item is shown again. The save stays on the store's
    `edit` path. Tests: a refused blur save keeps the text and `다시 저장` saves
    it; a refused save on an item switch keeps the draft for that item when it
    is shown again.
2.  A failed 매크로 read shows the row with the reason
    `매크로를 불러오지 못했습니다`, and a click reads again. Tests: the reason,
    and a rejected read followed by recovery and the 매크로 list.
3.  `resolveMacro` finds a reference by ID, then by name (spec 02), and the
    select checks the resolved ID. Test: an item whose `macro` is `찬양` shows
    찬양 with its tile and checks it in the list.

`edit` now takes one options object (`ItemEdit`) for the change, the notice
title, the target, and the retry.

Round 2 (codex2, Request changes), answered in one new commit:

1.  Memo drafts are never dropped by age. They are bounded by their items: a
    draft goes away when its save succeeds or when the service no longer has its
    item (a pushed service without it, or no service). The hard limit is a
    refusal, not an eviction: with 100 unsaved drafts, a new item's memo isn't
    accepted, the notice says `저장하지 못한 메모가 너무 많음`, and the typed
    text stays in the field. Editing a draft that already exists is always
    accepted. Tests at the limit (the 101st item is refused, the first draft
    stays, an existing draft can still change) and for a deleted item. The field
    now clears its typed text only after a successful save.
2.  The TSDoc on the non-exported `ItemEdit` fields is gone; the draft rule has
    a `NOTE(0913vision)` instead.
