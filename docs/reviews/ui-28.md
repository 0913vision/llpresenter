## What changed and why

The editor now mounts the 구성 row and the right-column preview and slide list.
Creation copies the selected order and opens a selected name field. Context
menus support rename/delete without changing the viewed order. 기본 is
protected; read-only songs still allow selection. Shared segments switch to
Select above five choices. Dialog validation and focus restoration use the
existing design system.

Rename/delete flush pending cached edits and call main's existing commands,
which rewrite service/template references. Own pushes update the checked
canonical document while current/undo/redo snapshots map the changed name. Lyric
undo cannot resurrect the old name or deleted order. Refusal, applied write
failure, uncertain transport failure, and deletion during a pending command
preserve the existing failure/reload behavior.

The ui-27 nit is addressed: `editedOrder` retains empty editing/copying orders.
Shared `playbackOrder` extracts Show's existing behavior, so a missing or empty
order displays file order. Main Show and the new list use the same helper.

The preview renders the selected local block and background in preview mode,
using the selected screen's current Look lyric style, layer visibility, and
solid/media background. It supports the three screen choices and broadcast
preview backdrop. Newer settings pushes supersede delayed reads. Thumbnail
clicks select and scroll the editor block while focus remains in the grid.
Repeated references retain their distinct selected occurrence. No preview or
thumbnail operation sends an output command or subscribes to live layers.

The list virtualizes rows, retains full logical keyboard navigation, and uses
the existing percentage size control. `TileList`/`ThumbnailGrid` now own
optional full-list ARIA positions, size, and orientation, so this host does not
write attributes into UI-owned nodes. This implements the TileList part of the
later assigned position-props task; migrating MediaStrip remains separate work.

## Quality and decisions

Only existing checked settings/content APIs are used. No dependencies or
contract changes. The settings list retains at most looks/screens. Virtual
thumbnail DOM scales with viewport height and overscan. Existing main tests
cover cross-file arrangement propagation; renderer fixtures do not pretend to
implement filesystem propagation.

Caption position is the selected source block's file position/count, including
when its cursor is outside the viewed order. The existing output renderer has no
stage-layout engine (`ScreenPreview` already records this TODO); this panel
supplies current Look lyric style/visibility/background for the stage screen
through its existing lyric layer. It does not add an output engine in UI's panel
request. Notice-time deduplication and the MediaStrip position-props consumer
remain the later assigned small tasks.
