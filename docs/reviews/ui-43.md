## What changed and why

Text import could read and preview a draft but could not save it without first
creating an empty library song. `content.edit` now accepts `song.import` with a
draft and either a new-song target or an overwrite target with ID and revision.
It returns the existing `EditResult`, including applied write failures.

Main generates new IDs through the existing helper. Overwrites retain the ID and
nested unknown fields, check revision and access before changes, replace known
fields, and stamp `updatedAt`. Duplicate normalized titles are refused. New
labels are registered with no color or jump key before the song is saved.
Removed arrangement picks are cleared in editable services and templates. Writes
reuse `ContentPersistence` and `Saver`, including recovery copies, atomic file
replacement, failed-save tracking, and retries.

## Limits and decisions

- Draft: 5,000 slides, 20,000 lyric lines, 1,000,000 serialized characters,
  1,000 arrangements, 20,000 arrangement picks, and 512 characters per name.
- Import cannot grow the global label list beyond 10,000 entries. A read-only
  label list may be used when no new label is needed; otherwise import is
  refused.
- Read-only services/templates stay untouched, matching existing arrangement
  edits.
- Atomicity is per file, as in existing content edits. Applied failures preserve
  in-memory changes and identify every failed file for retry.
